# Suran.Memory —— Alife 持久记忆的增强版

> 在官方 `Alife.Function.Memory`（持久记忆）的基础上重写：**压缩方式、标签格式、设置项全部沿用原版**，
> 只往上加它没有的能力——记忆总量上限、关键词检索、钉住、矛盾作废。

## 和原版一致的部分（这些没改）

| | 原版 | 本插件 |
|---|---|---|
| 压缩位置 | 摘要替换被压掉的那一段，位置不变 | **一致**，历史仍是一条连续时间线 |
| 标签格式 | `[记忆存档(等级-起-止)]` | **一致**，索引形如 `3-20261101054025-20261101145153` |
| 分层 | 同级攒够就升一级，到顶不再升 | 一致（`GroupSize` 默认 4） |
| 触发 | 条数阈值 + 概率 | 一致（`TriggerMessages` / `Probability`） |
| 思考通道 | 压缩时租用 | 一致（`ThinkingCompress`） |
| token 告警 | 超线写日志 | 一致（`TokenWarningThreshold`） |
| 关键词提示 | 命中关键词追加提示 | 一致（`RecallHintKeywords`） |
| 主动记忆 | `Memorize(level, name, synopsis, content)` | 同名能力，`MemoryRemember(title, level, importance, pinned, content)` |
| 原文落盘 | `Memory/L{n}/{索引}.txt` | **同一路径**，新老存档共用一个目录 |

`MemoryRecall` / `MemoryForget` 吃的也是原版那种索引，旧存档的索引直接能用。

## 增强的部分

**1. 记忆总量上限（原版没有）**
所有在上下文里的存档字数超过 `MaxBlockChars`（默认 6000）时，把最旧的移出上下文。原文仍在 archive 目录，`MemorySearch` 能搜到、`MemoryRecall` 能取回。

**2. 关键词检索（原版只能按索引取）**
中文二元组 + 英文词的倒排索引，支持关键词 / 等级 / 最近 N 天。搜的是全库，包括已经移出上下文的。

**3. 钉住**
`MemoryRemember(..., pinned: true)` 的条目永不被移出。

**4. 矛盾作废（借自 dsh-memory-tiers）**
压缩时提示词里会附上「已有存档清单」，如果这批内容推翻或纠正了某条旧结论，模型会输出一行 `替代：<索引>`。插件据此把旧条目标记为已作废——**不再进上下文，但摘要和原文都留在库里可查**，台账记一笔。效果是「说过的旧结论不会和新结论并存」。

**5. 按激活度淘汰（借自 dsh-soul 的记忆动力学）**
超容量时不再只比「重要度 + 时间」。每条的留存价值这样算：

```
A（可得性）= 逻辑斯蒂( ln Σ(now − tⱼ)^−0.5 )     tⱼ = 创建时刻 + 每次被检索的时刻
价值       = 重要度 × A × (1 + 0.05 × 命中次数)
```

ACT-R 的幂律衰减，一个参数，纯本地计算。它多认两件事：**一条三个月前压出来但反复被翻出来的记忆，比一条两个月前压出来、再没人提过的更该留**；间隔着被用到比连着被用到更强。被 `MemorySearch` / `MemoryRecall` 命中时记一次，淘汰时按价值升序走。

`ActivationEvict=false` 退回旧规则（重要度 → 时间）。

**6. 按时间翻旧账（借自 Mao.MemoryInject 的 `memwhen`）**
`MemorySearch` 多了 `when` 参数，直接吃中文时间说法：`昨天` `昨晚` `前天` `上周三` `上上周` `三天前` `上个月` `10 月 31 日` `最近 7 天`。模型不用自己算日期，也就不会算错。

认不出来时**不猜**——返回「没看懂，能认这些」。猜错的时间比不查更糟：它会拿「上周」的结果回答「上个月」的问题，而且自己不知道错了。

**7. 原文也能搜到（借自 dsh-soul 的 span 回捞）**
以前索引只建在「标题 + 摘要」上，于是有个说不出口的洞：**关键词只在原文里出现、摘要没提到时，永远搜不到**。而这恰恰是最需要检索的场景——摘要写得粗，细节全在原文。

现在检索会顺带扫原文（`SearchArchive`，默认开），命中不再是"命中过"，而是**带出那段证据**：

```
a1b2c3 L1 10-31 14:16 插件编译
    命令行是 node .build/harness，输出到 CompiledPlugins
```

摘录取「标识符密度最高的一段」而不是开头——两万字的原文，开头通常是寒暄。

原文不进倒排：一条 6000 字的原文要留几千个引用，400 条就是几十 MB 常驻；按需扫描是 400 个文件、几十毫秒，还带字符串缓存。工具调用不是每轮都发生，这笔交易划算。

**8. 原文锚点（借自 dsh-soul 的 `promoteUncovered`）**
摘要里写不进去、但猜不回来的东西单独存一行：

```
[记忆存档(3-20261101054025-20261101145153)] L3 11-01 05:40 插件编译修复
（摘要正文…）
[原文锚点] D:/Alife.Client · Runtime/PluginContext/CompiledPlugins · --no-incremental
```

从被压掉的原文里机械抽出**路径 / 版本号 / 命令行开关 / 大写错误码**，和摘要里的比对，只留「摘要没覆盖的」。花几十个字，换掉一次「翻遍全库也找不到」——模型编不出 `CompiledPlugins` 这个字符串，检索也检不到（摘要里没写）。

存在 `Facts` 字段而不是拼进 `Summary`，这样在界面上编辑摘要不会误删它。`FactsEnabled` 控制开关。

**9. 检索边界说清楚（借自 dsh-soul）**
每次检索末尾都带一行：

```
(检索范围：摘要 47 条 + 原文 43 篇，最早 10-31)
```

不写这句的话，在模型眼里「查不到」和「不存在」是一回事，它会把「我这儿没有」讲成「从来没有」。

**10. 落盘前隐去密钥**
用户在对话里贴 token 是常态（贴完还会说"帮我推上去"），摘要和原文都会把它带进磁盘。现在写盘前把 `sk-` / `ghp_` / `xox` / `AKIA` 形状的 token、`password=…`、`Bearer …`、URL 里的 `user:pass` 换成占位符。`RedactSecrets` 默认开。

**11. 该查的时候提醒它查（借自 dsh-soul 的重合度路由）**
用户这句话和「上下文里所有存档」的词面重合低于 20% 时，在消息后追加一句「先 MemorySearch 再回答，不要凭印象」。

解决的不是检索能力，是**检索意愿**：卡片看起来像全量，模型就凭它答，而答案其实躺在某条没人提过的旧存档里。有冷却时间（默认 120 秒），短消息（<8 字）不触发。`AutoRecallHint` 默认开。

**12. 回忆：没人问，但它自己浮上来（借自 Azuma.MemoryReverie 的机制）**
每 2~12 小时（可配）挑几条旧事推到对话里。和检索是两件事——检索是有人问你去翻，回忆是没人问它自己浮上来。

所以**挑谁不看相关度，看多久没被想起**：

```
A（可得性）= ACT-R 幂律衰减，创建算一次编码、每次被检索/回忆再算一次
排序后按 0.55^rank 加权抽样，无放回
```

不能纯按 A 升序（那样每次都挑同几条最老的，第三次就成复读），也**不能洗牌**——洗牌之后排名信息就没了，`count=1` 时「最尘封的」和「第二尘封的」各 50%，那就退化成抽签了。加权抽样的实测结果是：最尘封的那条命中率 64.5%（400 次），既明显偏向尘封，又不会每次一样。

同一条 `RecallCooldownHours`（默认 24 小时）内不再挑；已作废的、超出 `RecallMaxLevel` 的不挑。**L100 永久层不受层级限制**——它是人工钉住的约定，数字大不代表更抽象，恰恰最该被回味。

生成文本刻意收着，不是「你要回忆」的命令，而是描述发生了什么事：

```
(回忆时间到)
有些事没人提起，却自己浮了上来：

【三个月前（08-12） · 海边约定】
那天她说想去看海，最后定了威海……
（那时的原话：…）
```

下面三件事必须做对，否则会变成打扰：
1. **正在生成回复时顺延 30 秒**——回忆是插话，不能打断它自己正在说的话
2. **间隔随机**，不是固定周期——固定周期会让「忽然想起」变成准点报时
3. **帧率归一化**（`FrameCount % (1/ExpectedDeltaTime)`）——不论 30 帧还是 144 帧，检查逻辑每秒只跑一次

`RecallEnabled=false` 可完全关掉。设置页顶栏有「现在回忆一次」，模型也能自己调 `MemoryReminisce`。

**13. 已经在眼前的，不再塞一遍（借自 dsh-offline-memory 的注入去重）**

它那边的说法是「上下文已有不重复注入」——判断依据是文本重合。这边是同一个问题的另一种形态：上下文里的存档是**原位置留着**的，模型一直看得见，于是有两处重复：

| 地方 | 以前 | 现在 |
|---|---|---|
| 自动回忆 | 可能挑中正在上下文里的存档，把摘要再推一遍 | 跳过 `InContext` 的条目——「想起」的应该是**不在眼前**的事 |
| 回忆没挑出东西 | 照样 Poke 一句「回忆时间到」 | 什么都不说（没想起来就别出声） |
| `MemorySearch` 结果 | 不区分，模型看不出哪些手上已有 | 标 `〔摘要已在上下文〕`，并说明「摘要你手上就有，要原文才 Recall」 |
| `MemoryRecall` | 直接给原文 | 在上下文里时前置一句「摘要已在上下文，下面是原文」 |

判重不靠文本比对：`InContext` 是插件自己维护的精确状态，比字符串匹配可靠。

配套在系统提示里加了一条**冲突裁决**（也是 dsh 那句最要紧的话的改写）：

> 存档和当前对话冲突时，以**此刻听到的**为准，并直说「我记得的是 X，你现在说的是 Y」——不要为了保持前后一致悄悄改口，也不要拿旧存档去纠正主人。记忆是参考，不是事实。

存档是 assistant 消息，不写清楚的话，模型很容易把它当成「我刚说过的话」，或者拿三个月前的结论去顶撞眼前的人。

## 和状态插件连起来（Suran.Mood）

两个插件本该互相知道一点，但**只连一根线**，走文件不取模块实例：

```
Storage/<角色>/Mood/state.json   ← Suran.Mood 写，本插件只读
```

读不到就当"不知道"，全部退回中性值——状态插件没装、被禁用、正在重载，压缩和检索都不该因此停下。

| 用在哪 | 做什么 |
|---|---|
| 压缩时 | 把当时的心情/体力/亲近记进存档（`StateMood` 等三个字段）。读不到就留 `null`——**"不知道"不等于"她当时无所谓"** |
| 检索时 | 情绪一致性重排：此刻心情离某条存档当时的心情越近，越容易被想起（难过时先想起难过的事） |

重排的系数是 `1 ± MoodBiasStrength`（默认 0.25，即 ×1.25 ~ ×0.75），**只改顺序，不增不删**：召回边界仍然由关键词决定，情绪只决定先想起哪一条。没有快照的条目一律 ×1.0，不奖不罚。

这两个字段看着不起眼，但它们是归纳层的原料：从一堆没有温度的事实里，提炼不出信念。

## 同义扩展（字面搜不到时才有）

分词是二元组 + IDF。它能扛中文，但对同义词是瞎的：搜「记性」找不到写着「记忆」的存档，搜「翻脸」找不到写着「吵起来」的。

`QueryExpand`（默认开）在**结果不够时**才动：让小模型把关键词换三种说法再搜一遍，合并去重。

放在"结果不够"之后是有意的——每次检索都多付一次模型调用太贵；而绝大多数检索字面就够了。

失败不影响可用性：模型不可用、解析不出、扩出来的说法太长，一律按原词检索。

## 归纳：记忆 → 规律 → 信念

压缩只做一件事：把 100 条对话变成 1 条摘要。它**从来不做**另一件事：把这 8 条摘要变成 1 条规律——而后者才是人格，前者只是台账。

`patterns.json` 存的是一条条归纳：

```json
{
  "Theme": "被说任性",
  "Statement": "他说我任性的时候，多半是我在要东西",
  "Kind": 1,                         // 0=规律 1=信念
  "Evidence": ["1-20261031...", "2-20261102..."],
  "Confidence": 0.7
}
```

**每条归纳必须归到八章之一**（借自 dsh-xingxi 的记忆卡骨架）：

```
我是个谁 / 我是怎么说话的 / 对方是谁 / 我们怎么走到今天的
我们的约定 / 难忘的时刻 / 怎么跟对方相处 / 我们一起做的东西
```

为什么要骨架而不是让主题自由生长：自由生长三个月会碎成几十条同义条目，
每条只有一两条证据，等于没有归纳；而且散着的主题答不了「我是谁」——那才是人格的底座。
章名不在名单里就当没归章（宁可散着，也不要长出第九个游离的章）。名单可以在配置里改。

三条克制，缺一条这层就会变成"会编人格的机器"：

1. **证据少于 2 条不收**。模型很爱把单次经历说成"她总是"——那不叫规律，叫一次不愉快
2. **证据 id 必须真存在**。模型会编索引；编出来的引用比没有归纳更糟
3. **只增补、不自动作废**。推翻一条信念要人来做：模型今天心情不好就改人格，比不改更糟

触发：每攒够 `ReflectAfterArchives`（默认 6）条新存档，压缩结束后**后台**跑一次；也可以手动 `MemoryReflect`。查询用 `MemoryBeliefs`。

归纳**不注入上下文**——它在库里，要的时候查。理由和存档不一样：存档是"发生过什么"，模型需要一直在场；归纳是"她一般怎么想"，说出来就成了台词。

## 事实键：同一件会变的事只留最新

有些记忆记的是**会变的东西**，光看句子像不像判不出来：

- 「身高一米七」和「长胖到 55 公斤」几乎是两件事，词面上却很像
- 「拼团还没开」和「拼团开了」是同一件事的前后，词面上却不像

所以压缩时会顺手给一条**事实键**：「对象.方面」，比如 `他.身高`、`我.作息`、`约定.见面时间`。
**同一个键 = 同一件事** → 新的进来，旧的自动移出上下文并标作废（东西还在库里，能检索、能撤销）。

> ⚠️ 键里**不许写值**：写 `他.身高`，不是 `他.身高170`。
> 写了值就成了摘要——身高真变了，键也跟着变，两条永远碰不上。

**为什么需要它**：原来只靠模型在压缩时自己写「替代：某索引」——它得在几十条存档里认出
「这条推翻了那条」，还得把索引抄对。这件事它经常不做，或者做错。有了键之后，
取代判断从「模型回忆」变成「字符串相等」。

只认完全相同的键，不做模糊匹配：把 `他.身高` 和 `他.体重` 认成一件事，等于凭空抹掉一条记忆。
拿不准就留空——留空只是享受不到这个便利，给错键却会顶掉一条正经存档。

## 单字也能搜到

分词是二元组，所以「猫」「钱」「书」这种单字一个词都产不出来。以前这种情况会**静默退化成
"按时间倒序返回最近几条"**——看起来像搜到了，其实一条都没匹配，最坑的是它还很像"我确实查过"。

现在改成字面扫描：标题 + 摘要逐条比对，命中次数就是分；摘要里没有的再去原文里找一遍。
单字没有稀有度可言，所以这一档不做 IDF。

## 归纳主题不许烂开

自由生成主题跑三个月会碎成一堆同义条目（「被说任性」「嫌我任性」「说我作」）。
现在两道约束：

1. 提示词里明说：能装进已有主题就用**原词**，不要换个说法另开一条
2. 代码里再兜一次：规范化之后**互相包含**就算同一个主题，合并进去

只在长度 ≥2 时做包含判断——单字主题太容易误吞。

## 星云：她心里的东西长什么样

右下角有个「✦ 星云」，点开是一张图：

- **主题是星团**：归纳出来的规律/信念各成一团，团里的星就是支持它的那几条存档
- **散星在外圈**：只发生过一次的事，没有归到任何主题里
- **颜色按当时的心情**：低落偏冷蓝，高兴偏暖（用的是 `StateMood`）
- **亮度按重要度 + 新鲜度**：旧的会暗下去，但不会消失
- **同团的星连最近的邻居**：一串散点看不出关系，连上线才看得出"这几件事是一回事"
- 悬停看标题，点击看摘要和时间，滚轮缩放、拖拽平移
- 按钮上带星数（`✦ 星云 · 128 颗`），一眼能看出值不值得点开
- **鼠标移上去先弹一张小卡**（星数 / 主题数 / 前 4 个主题），点一下才铺开整片星云——
  和状态挂件同一套手感，都是"移上去展开、移开收起"（照 `1chuxin.TokenStats`）
- 按钮位置横竖独立可调（`NebulaButtonBottomPx` 默认 300、`NebulaButtonRightPx` 默认 14）。
  默认落在状态挂件之上——两个都靠右下角，写死的话会互相压住（旧默认 260 正好压住挂件顶端）
- 外观和状态挂件是同一套（同圆角、同毛玻璃、悬停亮边），右下角两枚按钮看起来是一套的

**展开后是一整页**，不是一块画布：顶栏有标题、统计和「同步 HH:MM:SS」、找一件事的搜索框、
重置视图；左侧是主题列表（点一个只看这一团）与心情色标图例；右侧是选中那颗的详情
（标题、时间、所属主题、当时的心情条、亮度条、摘要全文）；底栏写了操作方式，Esc 关闭。
画布本身加了背景星尘、虚线轨道环、星星发光、同团连线按主题着色、选中星的准星。

**同步是这次重点修的**。旧版顶栏数字只在第一次初始化时写一次，之后按钮星数在变、
打开后的 HUD 却停在旧值；详情面板也会在记忆删掉后继续显示旧内容。现在：

- 数据一到就 `renderUI()` 刷新顶栏 / 侧栏 / 悬停卡；重排后 `renderDetail()` 再刷一次详情
- 顶栏显示的是**这批数据到达的时刻**（不是界面绘制时刻），一眼能看出新不新
- 选中态按 `标题|日期` 记，数据刷新后还能找回；这条记忆真被删了就自动回到空态
- 轮询从 30 秒缩到 **5 秒**（数据没变就直接返回，不产生额外 eval）；
  设置页「打开星云」还会通过静态桥先强制重推一次，不用等下一轮
- 面板开着时数据变化会原地重画，不打断当前缩放和位置

数据走静态入口 `MemoryService.NebulaJson`，最多 300 颗星、12 个主题——兜住上限，
别让画布变成一片糊。

它不替代 `MemorySearch`：搜索回答"哪件事"，星云回答"**整体是什么形状**"。
一个是检索，一个是俯瞰。

## 目录

```
Storage\<角色>\Memory\
  L{n}\<等级>-<起>-<止>.txt      原文。和官方同名同位置，新老存档混在一个目录里
  History.json                  整段对话快照（官方同一格式）。重启后从这里恢复，含还没压的 L0 原文
  tiers\items.json              条目元数据（等级/起止/重要度/钉住/是否在上下文/被谁取代 + 摘要正文）
  tiers\ledger.jsonl            淘汰/作废/删除台账（先记账再动数据）
```

**历史持久化是必须的**：Alife 自身不保存会话，重启后线程是空的。官方插件靠 `History.json` 在 `OnStart` 里把整段对话塞回去，不写这个文件，重启就只剩存档摘要、未压缩的 L0 原文全没了。这版把同一件事补上了（`PersistHistory`，默认开）：

- 每条 assistant 消息落地后写一次（`SaveHistoryAsync`）
- 压缩、合并、界面上的编辑/删除/新增之后各写一次
- 启动时先 `LoadHistory` 恢复全部非 system 消息，**并把时间戳一起恢复**（否则重启后所有原文都盖成"启动时刻"，按时间检索全错），再按库补回缺席的存档消息

**和官方插件只能二选一。** 两边都订阅 `ChatHistoryAdd`、都会把历史压成存档，同时启用会各压一份，同一段对话出现两条摘要、两个文件、索引还不一样。所谓"复用官方目录"只是指**数据格式和位置一致**（所以换过来不用搬文件），不是能同时跑。

**原文按官方布局放**：`L{等级}/{等级}-{起}-{止}.txt`，和原版插件完全一样。好处是两边的文件能互相读——哪天你把官方插件装回来，它扫 `L{n}` 看到的就是完整的历史；反过来我这边也不复制、不搬家，只是把路径记在索引里。

官方那套只存得下「等级 + 起止时间」，而我这版多了四样：重要度、是否钉住、是否还在上下文、被哪条取代。这些只能另存一个文件，就是 `tiers\items.json`——但它只放元数据和摘要正文，**原文一律在 `L{n}` 里**，不存第二份。

## 设置页

`Module` 上挂了 `EditorUI = typeof(MemoryServiceUI)`，在角色设置里能直接看到这个插件的设置页，分两块：

**记忆库（可编辑）**——**默认收起**，点标题展开/收起，标题上直接显示「N 条 · 上下文 N 条」，免得改配置要滑很久。展开后列出全部条目（**等级从高到低**：L100 → L1，同级按时间倒序，最多 300 条），每条显示等级、时间、标题、状态标签（上下文/钉住/重要/已作废/无原文）和摘要预览。能做的事：

- **编辑**：改标题、摘要、重要度、钉住。改完会**同步替换历史里那条存档消息**，否则界面上改了、模型看到的还是旧文本
- **移出 / 放回上下文**：放回时按等级插回阶梯（放在第一个更高等级之前），不乱序
- **看原文**：直接展开 `L{n}/…txt` 的内容，不用去翻文件
- **定位原文**：打开资源管理器并**选中**这条对应的 txt（`explorer /select`），不用自己找
- **删除**：点一次变「确认删除」，再点才真删；原文文件挪到 `tiers/deleted/` 而不是直接删，误删能捞回来
- **打开库存位置**：直接弹出资源管理器到 `Storage\<角色>\Memory`，收起状态也能点
- **新增**（对应官方的 `Memorize`）：等级 / 标题 / 简述 / 内容四项，外加重要度、钉住、是否立刻进上下文。**简述常驻上下文**（模型一直看得到），**内容存进 `L{等级}/`**（只有 `MemoryRecall` 才翻得到）——这个两分法是官方就有的设计，不是我加的

所有写操作和自动压缩互斥（同一个信号量，压缩在跑时界面会提示「正在压缩/整理中」），避免两边同时改 `items`。

**配置**——顶栏显示「库里 N 条 · 在上下文 N 条 · 有原文 N 条 · 带锚点 N 条」，下面有「现在回忆一次」「打开星云」「导出完整上下文」。52 项配置按「压缩 / 容量 / 永久 / 检索 / 回忆 / 告警 / 旧数据」分段排开，每项下面一句说明它实际影响什么。

**导出完整上下文**——把模型眼下能看到的历史写成 `Storage\<角色>\Memory\context-dump.txt`，
头部给各段字数，正文分三段：系统提示全文 / 记忆存档（带 id、等级、字数）/ 对话消息（带角色、时间、字数）。
每次覆盖同一份，点完顶栏回一句「已导出 N 条 / N 字 → 路径」。

借鉴 dsh-memory-tiers 的 `/memory context`，但**不冒充请求报文原文**：Alife 的请求是运行时组装的，
插件只能读到 `ChatHistory`；各插件在 `ChatSend` 临时拼进用户消息的状态/提示、宿主在请求组装时
才追加的运行时段，是否出现在这份快照里取决于宿主写回历史的时机。文件开头的【说明】把这条写清楚了。

只读，不改 `items`、不触发压缩；和压缩互斥（走同一个 `Guarded`）。用来核对
「她到底看到了什么」——比如刚调完人味输出层，可以直接看历史里那几段的实际文本和字数。

**打开设置页会先自动刷一次。** 从磁盘重读 `tiers/items.json`、重建索引、重数待压原文（那个「L0 原文 N 条」以前只在压缩时才更新，一打开常常是 0，看着像没有待压的）。「刷新」按钮做的也是这件事——以前它只重渲染一遍，磁盘上改过的内容根本不反映。

自动刷新和压缩互斥：正在压缩时会被拒，顶栏会说一句，点「刷新」再试。

**内置压缩提示词可以直接看。** 压缩区有一个「查看内置提示词」，展开后是两套模板的完整原文（初次压缩 / 合并升级），每套带一个「填入上面的输入框」按钮——把模板连占位符原样拷进编辑框，在它基础上改。

不给看的话，那个`自定义压缩提示词`输入框等于要求人凭空写两千字，实际结果就是没人动它。

写法和 EmotionTTS 那套一致：手写 `RenderTreeBuilder` + AntDesign 控件，不走 `.razor`——宿主的 `CSharpCompiler` 只编译 `.cs`，razor 得离线预生成，改一个控件就要重新出文件。保存按钮由框架渲染，不用自己写。

## 短码、瘦身与"只给新情报"

四条参考 KiraAI 那套记忆插件（`KiraAI_Alife_memory_Z_plugin`）做的改动：

**1. 6 位短码**：完整索引 `3-20261031141657-20261101054025` 有 31 个字符，模型抄错一位就查不到。现在每条有个由 Id 哈希得来的短码（`k7f3a9`），稳定、定长、200 条实测不撞。`MemoryRecall` / `MemoryForget` 同时接受**短码、完整索引、索引片段、标题**——只有唯一命中才算数，不会猜。

**2. 检索返回瘦身**：不再每行吐 31 字符索引，改成 `短码 L等级 MM-DD HH:mm 标题 — 摘录`。摘录长度可配（`SearchExcerptChars`，默认 60，填 0 只给短码和标题）。

**3. 只给新情报**：模型很容易反复搜同一件事，把同样几条一遍遍灌回上下文。现在同一会话里已返回过的条目会被略过，并告它「另有 N 条已给过」；确实要看旧的，让它传 `allowSeen=true`。开关是 `SearchOnlyNew`。

**4. 永久记忆也有上限**：L100 本来是只进不出的，涨到几十条就是几万字常驻。现在 `PermanentMaxItems`（默认 12 条）/ `PermanentMaxChars`（默认 4000 字）超了就把**最不重要的移出上下文**——不删除、不降级，原文和钉住状态都在，随时能放回或检索到。想让它按语义取舍而不是按重要度，打开 `PermanentTidyByModel`，由模型挑 keep/archive（失败自动回退到按重要度）。

1. 放到 `Storage\Plugins\Suran.Memory\`
2. **先停用官方「持久记忆」**——两个都挂 `ChatHistoryAdd` 并压缩历史，同时开会互相踩

## 没做的两件事（以及为什么）

**没有独立的「每轮重算投影」。** dsh-soul 最核心的一招是卡片走 `systemPrompt.context`、不写进历史，所以压缩在结构上碰不到它。Alife 的注入口只有 `ChatSend`（改用户消息）和存档消息本身，**两者都会进历史**，做不到"不落历史"。硬做只能是伪造一条 system 消息，风险大于收益。

**没有装 Azuma.MemoryReverie。** 它做的是同一件事（不定期 Poke 旧记忆），但跟本插件的数据格式不兼容：它按 `内容概述` / `原始内容` 的代码块解析摘要，我们的存档是原始 transcript，取不到就会兜底成整段原文（一次 Poke 上万字）；而且它按 `Level > MaxLevel` 跳过，8 条 L100 永久记忆一条都不会被回忆起。第 12 条是按它的机制重做的，用 `items.json` 的摘要、按可得性排序、L100 单独纳入。

**没有做 Mao.MemoryInject 的双水位线。** 那是给「每轮自动召回」节流的；本插件只在检索意愿不足时给一句提醒（第 11 条），没有可节流的东西。
